### Shipping

You own what lands. Merge only the commit that the required gate and an independent verifier checked, from the bottom of the stack up, and only with authority: an explicit request to merge, or a repository policy that permits merging your own PRs.

1. Pass the repository's required gate on each PR's latest commit: CI where it runs on pull requests, otherwise the local gate the repository documents. Never merge with failing or pending checks.
2. Get an independent verdict per PR from a verifier that did not write it (on Claude Code, the `cstack:verifier` agent). It runs the change the way a user would, parent against head, with the project's verification skill when one exists, and ends with `PASS`, `PASS+NOTES`, or `FAIL` plus the commands and outputs behind it. For a change with no runnable behavior it checks the real artifact: validators, generated output, links, and each changed claim against its source. Green CI, a bot approval, and a read of the diff are not verdicts, because none of them runs the change. On `FAIL`, fix, push, and return to step 1.
3. A verdict covers one commit. When the head SHA changes for any reason, including a merge from the default branch, the new head needs the gate and a fresh verdict before it merges.
4. Land bottom-up, one PR at a time. Squash-merge with a head-commit guard so a later push cannot slip in: `gh pr merge <n> --squash --delete-branch --match-head-commit <sha>`. Without `gh`, call `PUT /repos/<owner>/<repo>/pulls/<n>/merge` with `merge_method=squash` and `sha=<sha>`, then delete the branch separately.
5. Read the result back: the PR shows merged into the default branch, not into a parent branch or only queued. For the next PR in a stack, retarget it to the default branch and merge the default branch into its branch (never rebase and force-push), resolve conflicts, then return to step 1 for its new head.
6. Stop at the first PR without a current verdict. Report what landed with commit SHAs, each verdict and who produced it, CI on the default branch after the merge, and anything left, such as branches the host would not delete.

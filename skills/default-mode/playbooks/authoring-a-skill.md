### Authoring a skill

1. Give the skill one recognizable outcome and a discriminating description.
2. Keep `SKILL.md` as the interface and put conditional detail in focused references, scripts, or assets.
3. Link every supporting file from the entrypoint and avoid copied manuals or placeholder files.
4. Validate metadata, paths, cross-skill routes, and the real workflow. Add a behavioral evaluation when selection or side effects are easy to regress.
5. Delete prose that does not change a decision.
